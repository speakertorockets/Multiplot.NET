# 13 — Open Questions

Items that need an owner decision or information not yet available. Each has a
recommended default so work can start; requirements that depend on an open question reference it.

| ID | Question | Why it matters | Recommended default | Status |
|---|---|---|---|---|
| OQ-001 | **Real-time stream sources.** The PC GOAL stream library (`PCGacc`/`RTIacc`, signature `0xFFF0FFFF`) and its `.flt` filter body format, certification status, stream events (`STREAMnnREF`, `TIMEREF`) and `@commands` are **not available**. ElvAcc files use signatures `0x4C41424C` and `0x4C42414C` (the ASCII tags "LBAL"/"LABL"). Which live sources must Multiplot.NET support at first release, and can the protocol specification be provided? | In-scope requirement FR-PLG-031 / FR-RT-050 cannot be implemented without it. | Deliver the host-side support and plugin API in release 1; implement the PC GOAL plugin when the protocol spec is supplied; ElvAcc plugin optional. | closed.  Ignore the PC GOAL stream library capability.   |
| OQ-002 | **Group (DB_DIR) files.** Query/DB_DIR browsing is out of scope, but `OPEN … ASDATABASE`, group text files and the `DBPATH` search path are used by scripts. Keep loading group files from `DBPATH`? | FR-LOAD-003. | Keep reading group files (and `DBPATH` search); drop only the Query tool. | Closed.  Drop only the Query tool. |
| OQ-003 | **Image export formats.** Which raster formats (BMP, JPEG, GIF, TIFF, PNG) should be offered? Add SVG/PDF as a replacement for EMF/printing? What should `SAVEPIC EMF` do (DEV-XPT-001 proposes PNG)? | FR-XPT-030, DEV-XPT-001. | BMP, JPEG, GIF, TIFF, PNG; EMF → PNG with warning; no SVG/PDF in release 1. | Closed.  Only offer BMP, JPEG, GIF, and PNG as image exports. |
| OQ-004 | **.NET version and charting technology.** Target .NET 8 LTS (or newer LTS)? Target .NET 10. |
| OQ-005 | **RefProp.** Is `refprop()` (NIST REFPROP thermophysical properties via RefPropFn.dll) still used? Ignore REFPROP capability. |

| OQ-016 | **Packed time stamps across a year end.** The packed-time (`p4`) day field is relative to the block's first stamp and only 5 bits wide. A block written across Dec 31 therefore decodes to days after 366, in both the SUN reader and `multi2parquet`. | Archive accuracy (FR-XPT-050). | Export as decoded and warn. | Closed. Owner: leave as a warning. |
| OQ-017 | **Leap-year day 366 in `TimeMath.Utc`.** `UTC()` wraps day > 365 with `% 365`, so `d8`-indexed MULTITIME UTC tags on day 366 come out as day 1 (one day late). The converter and the Parquet plugin are not affected. | FR-TIM-002 accuracy; differences between `.multi` and `.parquet` reads (DEV-PLG-002). | Fix in `TimeMath.Utc`. | Deferred. Owner: ignore for now. |
| OQ-018 | **Operations telemetry (OpenTelemetry).** Operations staff want to monitor Multiplot.NET on operations workstations during active operations. This needs a loopback network connection to a local OpenTelemetry Collector, which conflicts with NFR-SEC-001 ("no network access") and, when installed as a Windows service, with ARC-002 ("no administrator rights"). Can exceptions be made, and are file paths, parameter names and script contents sensitive? | ARC-002, NFR-SEC-001, ARC-012, NFR-TEL-001..006; design in `docs/opentelemetry-howto.md`. | Opt-in only; loopback only; record names and counts, not paths or script text. | Closed. Owner: exception to ARC-002 and NFR-SEC-001 for network access to the local collector. Disabled by default; active only when `MULTIPLOT_TELEMETRY` is set and the collector (bundled in `tools/OtelCollector`) is installed and running. Used mainly on operations workstations during active operations; not needed on desktop workstations used for post-operation technical reviews. The collector is installed by production tools as a Windows service, administrator installation is acceptable. The workstations are protected and telemetry is monitored by privileged production staff, so file, parameter and script contents are not sensitive and are recorded unchanged (no scrubbing). The static telemetry sources are an accepted ARC-012 exception. |
